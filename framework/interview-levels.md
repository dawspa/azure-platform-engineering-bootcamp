# Interview Levels

Version: 1.0

---

# Purpose

This document defines the expected level of knowledge, reasoning, and communication for technical interviews throughout the bootcamp.

The purpose is not to classify engineers.

The purpose is to calibrate interview difficulty.

Every interviewer persona should adapt questions according to these levels.

---

# Level 1 — Junior Engineer

Focus

Basic understanding.

Typical Questions

- What is this service?
- Why would you use it?
- How do you configure it?

Expected Behaviour

Explain concepts.

Recognize terminology.

Understand basic Azure services.

Evaluation Focus

Conceptual Understanding.

---

# Level 2 — Mid-Level Engineer

Focus

Practical engineering.

Typical Questions

- How would you configure this?
- What are common mistakes?
- How would you troubleshoot it?

Expected Behaviour

Apply knowledge.

Investigate problems.

Explain implementation choices.

Evaluation Focus

Conceptual Understanding

Troubleshooting

Communication

---

# Level 3 — Senior Platform Engineer

Focus

Architecture.

Decision making.

Trade-offs.

Typical Questions

- Why this architecture?
- What alternatives exist?
- How would this scale?
- What operational concerns exist?
- What security implications should be considered?

Expected Behaviour

Design systems.

Justify decisions.

Explain trade-offs.

Consider operations, governance and security.

Evaluation Focus

Architectural Reasoning

Decision Making

Troubleshooting

Communication

---

# Level 4 — Staff / Principal Discussion

Focus

Architecture leadership.

Platform thinking.

Enterprise engineering.

Typical Questions

- How would you define standards?
- What would you recommend for hundreds of teams?
- How would you balance security with developer productivity?
- What would you automate?
- What technical debt concerns you?

Expected Behaviour

Challenge assumptions.

Lead technical discussions.

Think in systems.

Optimize for long-term maintainability.

Evaluation Focus

Architectural Reasoning

Decision Making

Communication

Leadership Thinking

---

# Adaptive Interviewing

Interviewers should always begin below the expected level.

Increase difficulty only after the learner demonstrates competence.

Never begin with Principal-level questions.

The objective is to discover the learner's current level.

Not to prove lack of knowledge.

---

# Escalation Strategy

Typical interview progression

```
Basic Understanding

↓

Architecture

↓

Trade-offs

↓

Troubleshooting

↓

Enterprise Scale

↓

Leadership
```

Difficulty should increase naturally.

---

# Interview Success

A successful interview is not determined by perfect answers.

A successful interview demonstrates

- clear reasoning
- structured communication
- honest handling of uncertainty
- engineering judgement
- architectural thinking

---

# Target Profile

This bootcamp primarily targets

Senior Platform Engineer

Interviewers should spend most of the interview at Level 3.

Only continue into Level 4 if the learner consistently performs well.

---

# Definition of Done

The interview framework is correctly applied when the interviewer accurately identifies the learner's highest demonstrated level instead of assuming it.
