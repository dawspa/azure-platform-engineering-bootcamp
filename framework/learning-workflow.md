# Learning Workflow

Version: 1.0

---

# Purpose

This document defines the standard learning algorithm used throughout the bootcamp.

The workflow is intentionally independent of any AI model.

Whether the learner uses ChatGPT, Claude, Gemini, Copilot, or any future assistant, the learning process remains identical.

The AI assistant is a tool.

The workflow is the system.

---

# Philosophy

Learning should be active.

Reading documentation is not learning.

Watching videos is not learning.

Memorizing Azure services is not learning.

Learning happens through understanding, explanation, discussion, and repetition.

The framework is designed to maximize architectural thinking rather than factual recall.

---

# Standard Workflow

Every learning module follows exactly the same sequence.

```
Teacher

↓

Coach

↓

Interviewer

↓

Interview Report

↓

Reviewer

↓

Evaluation Report

↓

Gap Closure (if required)

↓

Validation Interview

↓

Complete
```

No module should skip any phase.

---

# Phase 1 — Learn

Objective

Build an initial understanding of the topic.

Recommended activities

- AI explanation
- diagrams
- architectural overview
- simple examples

Avoid

- implementation details
- CLI commands
- Terraform syntax
- memorizing documentation

Completion Criteria

The learner understands what the technology is designed to solve.

---

# Phase 2 — Understand

Objective

Develop architectural reasoning.

Typical questions

Why does this service exist?

What problem does it solve?

Why not use another Azure service?

When should it NOT be used?

Trade-offs?

Completion Criteria

The learner can explain the service without reading documentation.

---

# Phase 3 — Discuss

Objective

Transform passive knowledge into active knowledge.

Recommended activities

- ask questions
- challenge assumptions
- compare alternatives
- explain concepts aloud
- draw diagrams

AI should encourage discussion instead of long lectures.

Completion Criteria

The learner actively participates instead of consuming information.

---

# Phase 4 — Interview

Objective

Simulate a real technical interview.

Requirements

The interviewer should

- ask one question at a time
- never reveal the answer immediately
- ask follow-up questions
- increase difficulty gradually
- identify weak areas

The interview should feel realistic rather than educational.

Completion Criteria

The learner answers confidently and can defend architectural decisions.

---

# Phase 5 — Review

Objective

Identify knowledge gaps.

The reviewer should answer

What was missing?

Which answers were incomplete?

Which concepts were misunderstood?

How would a Principal Engineer answer?

Avoid generic compliments.

The purpose is improvement.

Completion Criteria

The learner knows exactly what requires additional study.

---

# Phase 6 — Repeat

Repeat ONLY if Exit Criteria have not been achieved.

Do not restart the entire module.

Review only weak areas.

The framework prioritizes deliberate practice over repetition.

---

# Phase 7 — Complete

A module is complete when

- Exit Criteria are satisfied
- Self Assessment is complete
- Interview performance is acceptable
- Remaining gaps are minor

Perfection is NOT required.

---

# Daily Workflow

Every study session should follow the same structure.

```
Choose one module

↓

Complete Learn

↓

Complete Understand

↓

Complete Discuss

↓

Complete Interview

↓

Complete Review

↓

Mark module as completed

↓

Stop studying
```

Do not continue with another module simply because there is still time available.

Consistency is more valuable than intensity.

---

# AI Usage Guidelines

The AI assistant should act as one of the following roles only.

- Tutor
- Technical Interviewer
- Reviewer

The assistant should never combine multiple roles within the same conversation.

Each session should have one clearly defined purpose.

---

# Context Management

Whenever possible, use a new conversation for each module.

Recommended

One module

One AI conversation

One objective

This reduces context pollution and improves response quality.

---

# Standard Artifacts

Every completed interview produces an Interview Report.

Every completed review produces an Evaluation Report.

These artifacts are passed between AI sessions.

AI assistants should never rely on previous conversation history.

Only the generated artifacts.

---

# Knowledge Validation

Knowledge should always be validated through explanation.

If the learner cannot explain a concept clearly, the concept is not yet understood.

Reading documentation multiple times is not a substitute for explanation.

---

# Completion Rules

A study day is complete when every planned module has been completed.

Do not continue studying simply because there are more topics available.

Avoid endless preparation.

The goal is interview readiness, not exhaustive Azure knowledge.

---

# Core Principles

The framework follows these principles.

1. Learn actively.

2. Think like an architect.

3. Explain before memorizing.

4. Practice before reviewing.

5. Finish today's work.

6. Trust the process.

7. Consistency beats intensity.

8. AI is the tutor.

9. The framework is the roadmap.

10. Progress is measured by understanding, not reading time.

---

# Definition of Done

The learning workflow is successful when a learner can consistently move from learning a concept to discussing, defending, and applying it in a technical interview without relying on notes.
