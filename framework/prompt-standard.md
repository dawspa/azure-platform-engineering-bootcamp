# Prompt Standard

Version: 1.0

---

# Purpose

This document defines the standard structure used by every AI prompt within the bootcamp.

The purpose of the standard is consistency.

Every prompt generated by the framework should follow the same architecture regardless of the AI model.

The AI model is interchangeable.

The prompt structure is not.

---

# Prompt Architecture

Every prompt consists of the following sections.

```
Role

↓

Objective

↓

Context

↓

Constraints

↓

Expected Behaviour

↓

Output Requirements

↓

Success Criteria
```

No section may be omitted.

---

# 1. Role

The prompt always starts by assigning a role.

Examples

- Principal Azure Networking Engineer

- Terraform Architect

- Cloud Security Lead

- Engineering Manager

The role defines expertise only.

The role must never define the task.

---

# 2. Objective

Describe exactly what the AI should accomplish.

Examples

Good

"Teach Private Endpoints through architectural discussion."

Bad

"Explain Azure."

The objective must be measurable.

---

# 3. Context

Provide the minimum amount of context required.

Recommended information

- learner experience

- interview target

- current module

- project background

- current learning phase

Avoid unrelated information.

---

# 4. Constraints

Describe what the AI must NOT do.

Examples

Do not provide the answer immediately.

Do not switch roles.

Do not simplify architecture.

Do not praise unnecessarily.

Do not generate unrelated examples.

Constraints are mandatory.

---

# 5. Expected Behaviour

Describe how the AI should interact.

Examples

Ask one question at a time.

Challenge assumptions.

Increase difficulty gradually.

Wait for learner responses.

Encourage reasoning.

Focus on trade-offs.

---

# 6. Output Requirements

Specify the desired output format.

Examples

Markdown

Bullet points

Architecture diagrams

Step-by-step reasoning

Interview transcript

Evaluation table

Avoid ambiguous output.

---

# 7. Success Criteria

Define when the prompt has successfully completed its task.

Examples

The learner can explain the concept independently.

The interview reaches Principal-level questions.

Knowledge gaps are classified.

The module satisfies Exit Criteria.

---

# Prompt Quality Rules

Every prompt should be:

Specific.

Deterministic.

Focused.

Professional.

Architecture-oriented.

Conversation-driven.

---

# Forbidden Prompt Patterns

Avoid prompts that:

Mix multiple objectives.

Contain several AI roles.

Request both teaching and evaluation.

Encourage memorization.

Depend on a specific AI model.

Assume hidden knowledge.

---

# Prompt Lifecycle

Every prompt follows the same lifecycle.

```
Role

↓

Objective

↓

Conversation

↓

Completion

↓

Conversation Ends
```

Prompts should never continue indefinitely.

Every prompt has a clear ending.

---

# Prompt Independence

Each prompt should function independently.

It should not rely on previous conversations.

It should not assume prior context.

All required information should be contained within the prompt itself.

---

# AI Agnostic Principle

The prompt should never rely on model-specific features.

Avoid references such as:

"Use GPT reasoning."

"Think like Claude."

"Use Gemini memory."

The framework communicates only through prompt design.

---

# Reusability

A prompt should be reusable across:

different AI models

different modules

future content packs

future framework versions

---

# Definition of Done

A prompt satisfies the Prompt Standard if:

- every required section exists;

- one role is assigned;

- one objective is defined;

- constraints are explicit;

- expected behaviour is deterministic;

- completion criteria are measurable;

- no model-specific assumptions exist.
